# Audio Event Detection 模型训练与部署契约

> 版本：1.1  
> 更新日期：2026-06-20  
> 适用模型：`model/model_int8.tflite`

模型在 openvela Sim 中的接入、黄金测试和 ALSA 联调步骤见
[开发文档.md](开发文档.md)。

## 1. 文档目的

本文档记录当前训练模型的真实输入输出、数据与评估原则、INT8 转换要求，以及固件端必须复现的前处理契约。

旧版文档中的“13 维 MFCC 单帧分类”不是当前模型的训练方式。当前模型以 1 秒音频片段生成 `49x40` log-mel 特征，并对完整时间窗口进行分类。

## 2. 当前模型卡

### 2.1 基本信息

| 项目 | 值 |
|---|---|
| 模型任务 | 1 秒音频事件分类 |
| 网络类型 | 小型 DS-CNN |
| 目标事件 | `knock`、`cough` |
| 拒识类别 | `background`、`silence` |
| 参数量 | 1548 |
| 量化方式 | 权重和激活全 INT8 |
| TFLite 大小 | 11376 bytes |
| TFLite SHA-256 | `29b6931127a91a3a5fd75e9633f1f109c44070a8c28e9aae8be89c13949f4a84` |
| 测试准确率 | 88.65% |
| 误报率 | 2.40% |
| 漏报率 | 17.48% |

准确率来自 `metadata.json` 中保存的离线测试结果，不代表目标开发板和现场声学环境中的最终表现。

### 2.2 类别映射

类别顺序是模型接口的一部分，不允许由文件名排序或业务代码自行推导。

```text
0 -> knock
1 -> cough
2 -> background
3 -> silence
```

`background` 表示存在非目标环境声音；`silence` 表示低能量或无明显声音。两者都用于降低误报，不计作比赛要求中的目标事件类别。

## 3. 输入特征契约

### 3.1 已确认参数

| 参数 | 值 |
|---|---|
| 采样率 | 16000 Hz |
| 音频长度 | 1000 ms |
| 音频采样数 | 16000 |
| 分析窗口 | 30 ms，480 samples |
| 帧移 | 20 ms，320 samples |
| 帧数 | 49 |
| Mel bins | 40 |
| 特征后端 | `tensorflow_log_mel` |
| 特征形状 | `[49, 40, 1]` |
| 展平长度 | 1960 |

### 3.2 必须从训练端补齐的参数

当前 `metadata.json` 不足以独立复现 log-mel。下一次导出模型时必须同时保存：

- PCM 到浮点的缩放规则。
- 是否做去直流、预加重或幅值归一化。
- 窗函数类型及参数。
- FFT 点数。
- 功率谱或幅度谱定义。
- Mel 频率上下限和 Mel 标度实现。
- 对数底数、epsilon 或动态范围裁剪。
- 是否做均值方差归一化。
- 展平顺序。

这些参数不能靠固件端“取常用值”补齐。不同实现即使输出形状同为 `49x40`，数值分布也可能完全不同。

### 3.3 黄金测试向量

训练导出流程应为至少 3 段代表性 WAV 保存以下文件：

```text
golden/
├── knock.wav
├── knock_log_mel_f32.bin
├── knock_input_int8.bin
├── knock_output_int8.bin
├── cough.wav
├── background.wav
└── manifest.json
```

固件端测试依次验证：

1. 同一 WAV 产生相同帧数和 Mel bins。
2. 浮点 log-mel 与训练端误差满足约定容差。
3. 量化后的 1960 字节输入一致或仅有可解释的舍入差异。
4. TFLite Micro 与桌面 TFLite 的输出类别一致。

没有黄金向量时，模型接入失败很难判断是前处理、量化还是推理框架问题。

## 4. 数据集设计

### 4.1 数据组织

推荐使用以下逻辑类别：

```text
dataset/
├── knock/
├── cough/
├── background/
└── silence/
```

每个训练样本应对应一个固定 1 秒片段。长音频中的稀疏事件需要先定位活动区域，再围绕事件切片；不能把整段音频的所有帧都标成事件。

### 4.2 事件切片

推荐流程：

1. 统一重采样为 16 kHz 单声道。
2. 使用能量或事件标注定位有效区域。
3. 合并相邻活动片段形成事件簇。
4. 围绕事件簇生成 1 秒窗口。
5. 对背景长音频使用受限滑窗采样，避免背景数量压倒目标事件。
6. 保存切片来源、起止时间和标签到 manifest。

事件不足 1 秒时在两侧补背景或零值；事件超过 1 秒时可生成多个有重叠窗口，但必须保留来源关系。

### 4.3 数据集划分

训练、验证、测试必须在“原始录音文件或录音场景”层面划分，再生成切片。禁止将同一原始录音的相邻切片随机分到不同集合，否则测试指标会因数据泄漏虚高。

建议：

- 训练集 70%-80%。
- 验证集 10%-15%。
- 测试集 10%-15%。
- 自录数据按设备、距离、房间或录制轮次分组切分。
- 保存 `dataset_manifest.json`，记录随机种子和来源文件。

### 4.4 数据增强

增强必须在波形域、提取 log-mel 之前执行：

- 随机增益。
- 时间平移，但目标事件不能移出窗口。
- 不同信噪比的真实背景混合。
- 不同距离或房间的脉冲响应卷积。
- 轻量时间伸缩或音高变化，仅在不改变事件语义时使用。

验证集和测试集不做随机增强。

## 5. 模型训练

### 5.1 推荐网络约束

当前模型采用适合 MCU 的小型 DS-CNN 路线。后续训练应优先保持以下原则：

- 只使用 openvela TFLite Micro 已提供的算子。
- 使用 Conv2D、DepthwiseConv2D、Mean、FullyConnected 和 Softmax 等基础算子。
- BatchNorm 在转换前折叠到卷积参数。
- 避免动态 shape 操作；能使用静态 reshape 时，不生成额外的 Shape/StridedSlice/Pack。
- 以端侧总延迟和 Tensor Arena 为约束，不只比较参数量。

### 5.2 训练输出

一次可复现训练至少应产出：

```text
output/<run_name>/
├── best_model.keras
├── model_float.tflite
├── model_int8.tflite
├── model.cc
├── model.h
├── metadata.json
├── feature_config.json
├── labels.txt
├── metrics.json
├── confusion_matrix.csv
├── training_history.csv
├── dataset_manifest.json
├── threshold_scan.csv
└── golden/
```

当前仓库只复制了部署所需的模型和简化元数据，尚不能仅靠仓库内容重新训练同一模型。

## 6. INT8 量化

### 6.1 代表性数据集

代表性数据必须来自训练集，并覆盖：

- 两个目标事件。
- 安静和高能量背景。
- 不同音量、距离和噪声条件。
- log-mel 特征的实际极值范围。

不要从测试集抽取量化校准样本。

### 6.2 当前模型量化参数

```text
input:  int8[1,1960], scale=0.101961, zero_point=-128
output: int8[1,4],    scale=0.00390625, zero_point=-128
```

输入量化：

```text
q = clamp(round(real_value / 0.101961) - 128, -128, 127)
```

输出反量化：

```text
probability = (q + 128) * 0.00390625
```

固件实现应从 tensor 的 `params.scale` 和 `params.zero_point` 读取参数，以上常量只用于契约检查，不建议在推理逻辑中重复硬编码。

### 6.3 量化验收

- 比较 FP32 与 INT8 的整体准确率。
- 比较每类 Precision、Recall 和混淆矩阵。
- 单独检查弱类别的漏报变化。
- 使用黄金输入比较桌面 TFLite 与 TFLite Micro 输出。
- 记录量化前后模型大小和目标板延迟。

## 7. TFLite Micro 部署检查

### 7.1 模型文件

当前仓库包含：

| 文件 | 用途 |
|---|---|
| `model_int8.tflite` | 原始 FlatBuffer，用于结构检查和桌面验证 |
| `model.cc` | 16 字节对齐的只读模型数组 |
| `model.h` | `g_audio_event_model` 声明 |
| `metadata.json` | 模型输入、类别和离线指标 |

`model.cc` 与 `.tflite` 是同一模型的不同载体。固件编译使用 `model.cc`，不要在运行时从文件系统加载 `.tflite`。

### 7.2 实际算子

模型 FlatBuffer 已检查，schema version 为 3，包含：

| 算子 | 版本 |
|---|---:|
| SHAPE | 1 |
| STRIDED_SLICE | 1 |
| PACK | 1 |
| RESHAPE | 1 |
| CONV_2D | 3 |
| DEPTHWISE_CONV_2D | 3 |
| MEAN | 2 |
| FULLY_CONNECTED | 4 |
| SOFTMAX | 2 |

部署前必须确认当前 openvela TFLite Micro resolver 能注册全部算子。后续重新导出时，优先使用静态输入 shape，尝试移除前三个仅为动态 reshape 服务的算子。

### 7.3 Tensor Arena

Arena 大小不能从 `.tflite` 文件大小推导。首次集成建议从 64-96 KB 起步，`AllocateTensors()` 成功后打印实际使用量，再预留安全余量。最终文档应记录目标开发板上的实测值。

### 7.4 Sim 验证层级

模型部署验证分为三个层级：

| 层级 | 输入 | 目的 |
|---|---|---|
| `SIM-MODEL` | 黄金 `int8[1960]` | 验证 resolver、Arena、Invoke 和输出量化 |
| `SIM-FILE` | 固定 1 秒 PCM | 验证 log-mel、输入量化和最终类别 |
| `BOARD` | 真实麦克风 | 验证目标架构性能和现场识别效果 |

Sim 的分类一致性可以证明软件链路正确，但 Sim 延迟不能替代 MCU 推理速度，Sim 内存结果也应在启用目标优化内核后重新测量。

## 8. 阈值与事件级评估

模型元数据建议 `knock=0.75`、`cough=0.75`，连续 2 次推理满足阈值后告警。该值作为板端初始配置。

最终阈值应在独立验证集上按类别扫描，不能只看 argmax 准确率。至少记录：

- `knock` Precision、Recall、F1、误报次数。
- `cough` Precision、Recall、F1、漏报次数。
- 每小时背景音频误报数。
- 从事件开始到告警的端到端延迟。

事件级评估需要把相邻窗口的同类预测合并为一次事件，避免把一次持续咳嗽统计成多次正确或多次误报。

## 10. 模型更新检查清单

更换模型时必须同时更新并验证：

- [ ] `model_int8.tflite`、`model.cc`、`model.h` 来自同一次导出。
- [ ] `metadata.json` 和 `labels.txt` 的类别顺序一致。
- [ ] 输入时长、特征形状和前处理参数未漂移。
- [ ] 输入输出类型及量化参数与固件检查一致。
- [ ] Resolver 覆盖新模型全部算子。
- [ ] 黄金测试向量通过。
- [ ] Tensor Arena 在目标板重新测量。
- [ ] 阈值基于新模型重新扫描。
- [ ] 文档中的离线指标和板端指标同步更新。

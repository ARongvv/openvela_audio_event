# 音频事件检测比赛执行计划

> 版本：2.1  
> 更新日期：2026-06-20  
> 基线模型：`knock / cough / background / silence` 全 INT8 模型

具体开发命令、模拟器模式和测试用例见 [开发文档.md](开发文档.md)。

## 1. 总体策略

初赛不再重新设计模型路线，而是围绕已经训练完成的模型建立可验证的端侧闭环：

```text
模型契约确认
  -> 黄金测试向量
  -> openvela log-mel
  -> TFLite Micro 推理
  -> 麦克风与环形缓冲区
  -> 阈值/去抖/告警
  -> 性能测试与提交材料
```

两个目标事件为 `knock` 和 `cough`；`background`、`silence` 用于拒识。初赛优先保证闭环稳定、可重复和可测量，再做复赛扩展。

开发环境按以下顺序推进：

```text
NuttX 原生 Sim 文件模式
  -> NuttX 原生 Sim ALSA 麦克风
  -> 可选 Goldfish/QEMU 系统集成
  -> 真实开发板最终验收
```

Sim 用于功能和稳定性验证；比赛提交中的目标板延迟、RAM、功耗和现场识别效果必须重新实测。

## 3. 初赛实施阶段

### 阶段 A：冻结模型契约

目标：确保训练端、模型文件、文档和固件对同一接口达成一致。

任务：

1. 固定采样率为 16 kHz、单声道、1 秒窗口。
2. 固定特征为 `49x40` TensorFlow log-mel。
3. 固定类别顺序：`knock, cough, background, silence`。
4. 固定 INT8 输入输出维度和量化参数。
5. 从训练代码补齐 FFT、窗函数、Mel 频率范围、log 规则和归一化参数。
6. 保存模型哈希，避免 `.tflite`、`model.cc`、元数据来自不同训练轮次。

交付物：

- 完整 `feature_config.json`。
- `labels.txt`。
- 更新后的 `metadata.json`。
- 模型导出记录和 SHA-256。

验收：仅凭仓库中的模型资产和训练环境说明，可以确定模型全部输入输出语义。

### 阶段 B：在原生 Sim 建立黄金测试链路

目标：在接入真实硬件前证明前处理和推理数值正确。

任务：

1. 选择 `knock`、`cough`、`background`、`silence` 代表性 WAV。
2. 训练端导出浮点 log-mel、量化输入和 TFLite 输出。
3. 在 PC 或 openvela 文件输入模式下运行固件 DSP。
4. 对比 Python 与 C/C++ 特征。
5. 对比桌面 TFLite 与 TFLite Micro 输出。

交付物：

- `golden/` 测试数据。
- 自动比较脚本或单元测试。
- 特征最大误差、平均误差和分类一致性记录。

验收：四类代表样本在桌面 TFLite 和 TFLite Micro 上输出类别一致；数值差异有明确容差。

### 阶段 C：在原生 Sim 接入 TFLite Micro

目标：使仓库中的模型在 openvela 应用内完成真实推理。

任务：

1. 将 `event_classifier.c` 改为 C++ 实现并保留 C API。
2. 将 `model/model.cc` 加入 CMake 和 Make 构建。
3. 注册实际使用的 9 类 TFLite 算子。
4. 使用静态 Tensor Arena，先保守分配再测量收缩。
5. 初始化时校验 schema、tensor 类型、shape 和量化参数。
6. 实现 INT8 输入量化和输出反量化。
7. 对错误路径打印可定位的信息。

交付物：

- 可编译的 TFLM 推理封装。
- 固定输入特征的推理日志。
- 实际 `arena_used_bytes()`。

验收：应用不再返回伪造的均匀概率，黄金输入能够得到预期类别。

### 阶段 D：实现端侧 log-mel

目标：在目标平台上生成与训练端一致的 `[49,40]` 特征。

任务：

1. 替换旧 13 维 MFCC 接口。
2. 使用 openvela 已集成的 FFT 能力实现前处理。
3. 固定所有中间缓冲区，避免推理循环动态分配。
4. 检查边界帧数和展平顺序。
5. 添加黄金 WAV 和特征测试。
6. 测量每次特征提取耗时和内存。

交付物：

- log-mel 实现和测试。
- Python/C 特征对比报告。
- DSP RAM 和耗时数据。

验收：黄金测试通过；连续调用无内存增长或输出漂移。

### 阶段 E：接入 Sim ALSA 麦克风

目标：从真实数字麦克风持续获得模型所需的 1 秒 PCM。

任务：

1. 先使用 `nxrecorder` 验证 Sim 的 `/dev/audio/pcm0c`。
2. 配置 16 kHz、16-bit、单声道。
3. 实现短读处理和 PCM 格式转换。
4. 实现 16000 samples 以上的环形缓冲区。
5. 初始每 250 ms 取最近 1 秒运行一次推理。
6. 增加设备错误计数与重新初始化。

交付物：

- 麦克风采样日志。
- PCM 录制回放样本。
- 连续采集稳定性结果。

验收：Sim ALSA 至少连续运行 30 分钟，无崩溃、缓冲区越界或不可恢复的音频错误。随后在目标板上替换设备 source 并重新完成同类测试。

### 阶段 F：事件策略与告警

目标：把窗口级概率转换成稳定、可解释的事件告警。

初始策略：

```text
knock >= 0.75，连续 2 次 -> 告警
cough >= 0.75，连续 2 次 -> 告警
background / silence       -> 不告警并清除连续计数
告警后进入 1-2 秒冷却时间
```

任务：

1. 删除 `event_id > 0` 形式的告警判断。
2. 按类别保存阈值和连续命中计数。
3. 串口打印时间、类别、概率和触发原因。
4. 接入 LED 或蜂鸣器作为可视/可听告警。
5. 在独立验证数据上扫描每类阈值。
6. 将相邻窗口合并为事件后统计误报和漏报。

验收：敲击和咳嗽均能触发；背景、静音及常见干扰声不触发；一次持续事件不会产生密集重复告警。

### 阶段 G：性能与稳定性验收

必须记录：

| 指标 | 当前值 | 目标板实测 |
|---|---:|---:|
| 模型大小 | 11376 bytes | 同构建映射核对 |
| 离线准确率 | 88.65% | 不适用 |
| 离线误报率 | 2.40% | 补现场值 |
| 离线漏报率 | 17.48% | 补现场值 |
| 特征耗时 | 待测 | 待测 |
| 推理耗时 | 待测 | 待测 |
| 端到端告警延迟 | 待测 | 待测 |
| Tensor Arena | 待测 | 待测 |
| 应用峰值 RAM | 待测 | 待测 |
| 连续运行时间 | 待测 | >= 30 分钟 |

模拟器阶段的数据单独记录为 `SIM-FILE` 或 `SIM-ALSA`，不能填入“目标板实测”列。

测试场景至少覆盖：

- 安静环境中的近距离事件。
- 1 m、3 m 等不同距离。
- 音乐、说话、键盘和环境噪声。
- 连续多次敲击和连续咳嗽。
- 音频短读或设备暂时异常。

### 代码

- 完整采集、log-mel、TFLM、事件判定和告警闭环。
- 明确的 Kconfig、CMake 和 Make 配置。
- 黄金测试和必要的单元测试。

- README：构建、配置、运行和常见错误。
- 架构文档：真实运行链路、接口和资源占用。
- 模型文档：训练数据、特征、量化和指标。

### 演示

演示顺序建议固定为：

1. 启动 `audio_event`，打印模型和音频配置。
2. 展示静音/背景无告警。
3. 演示敲击告警。
4. 演示咳嗽告警。
5. 展示连续运行和性能日志。
6. 展示异常恢复或重启后可重复运行。

## 5. 复赛优化路线

初赛闭环稳定后，按收益和风险排序：

1. **鲁棒性提升**：补不同设备、距离、房间和噪声数据，重点降低咳嗽漏报。
2. **模型优化**：重新导出静态 shape 模型，移除 Shape/StridedSlice/Pack，比较 Flash、Arena 和延迟。
3. **类别扩展**：增加 1-2 类事件，同时重做背景负样本和阈值评估。
4. **低功耗**：使用低成本能量门控，在安静时降低完整 log-mel 和推理频率。
5. **远程告警**：本地告警稳定后再增加 MQTT/HTTP，上报失败不能阻塞采集。
6. **开发板适配**：整理 codec、I2S、defconfig 和烧录说明，形成独立适配文档。

## 6. 风险清单

| 风险 | 影响 | 处理方式 |
|---|---|---|
| log-mel 参数缺失 | 模型在板端近似随机 | 从训练脚本导出完整配置和黄金向量 |
| 类别顺序漂移 | 告警类别错误 | 单一常量表并在初始化时检查输出维度 |
| TFLM 算子遗漏 | `AllocateTensors` 或 `Invoke` 失败 | 从 FlatBuffer 生成 resolver 清单 |
| Tensor Arena 估算错误 | 初始化失败或浪费 RAM | 先放大实测，再按使用量收缩 |
| 按窗口统计指标 | 事件数据看似虚高 | 合并相邻窗口后做事件级评估 |
| 咳嗽漏报偏高 | 现场得分下降 | 补事件切片、困难样本和类别独立阈值 |
| 过早做复赛功能 | 初赛闭环不稳定 | 按阶段验收，闭环完成后再扩展 |

## 7. 完成定义

初赛版本只有同时满足以下条件才算完成：

- [ ] 真实麦克风输入，不使用全零或预置特征代替演示。
- [ ] 固件 log-mel 与训练端通过黄金测试。
- [ ] TFLite Micro 运行当前 INT8 模型。
- [ ] `knock`、`cough` 两类均有稳定告警。
- [ ] `background`、`silence` 不触发告警。
- [ ] 提供误报、漏报、延迟、RAM 和连续运行数据。
- [ ] 构建、烧录和运行步骤可由其他人复现。
- [ ] 数据集和第三方组件许可说明完整。

# 性能与评估

本文记录 `ccf_audioevent` 当前部署模型和 ESP32-S3 DevKit 真机路径的基础指标。指标分为
离线模型评估和端侧运行观测，两者口径不同，不直接混算。

## 评估对象

当前部署路径：

```text
ESP32-S3-N16R8 DevKit + INMP441 + 0.96 寸 I2C OLED
```

当前部署模型：

```text
app/audio_event/model/model_int8.tflite
```

模型输入契约：

| 项目 | 值 |
| --- | --- |
| 采样率 | 16 kHz |
| 音频窗口 | 1 秒 |
| 原始输入 | mono int16 |
| 特征 | log-mel + delta |
| 特征形状 | 49 x 40 x 3 |
| 类别顺序 | knock, cough, background, silence |
| 量化 | int8 |
| 模型大小 | 11,984 bytes |
| 参数量 | 2,148 |
| Tensor arena 配置 | 65,536 bytes |
| Tensor arena 实测使用 | 22,708 bytes |

来源：

- `app/audio_event/model/metadata.json`
- `app/audio_event/model/model_int8.tflite`
- `logs/演示日志.md`

## 阈值口径

当前真机配置：

| 事件 | 阈值 | 连续命中 |
| --- | ---: | ---: |
| knock | 380 permille | 2 |
| cough | 750 permille | 2 |

说明：

- 咳嗽在端侧实测中概率峰值更明显，保留较高阈值以降低误报。
- 敲门在 INMP441 实录中概率经常分散在 knock/cough/background 之间，因此当前使用较低
  阈值，并依赖连续命中策略过滤孤立误报。
- 现场环境变化后，应优先用 `audio_record` 导出 WAV，再基于实录数据重新扫阈值。

离线阈值扫描参考：

| 事件 | 阈值 | TP | FP | FN | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| knock | 0.40 | 85 | 9 | 7 | 90.43% | 92.39% | 91.40% |
| cough | 0.75 | 70 | 7 | 14 | 90.91% | 83.33% | 86.96% |

## 端侧延迟基础数据

推荐测量命令：

```text
nsh> audio_event --device /dev/audio/pcm_in1 --audio-stats --profile --no-oled
```

基础观测环境：

| 项目 | 值 |
| --- | --- |
| 板卡 | ESP32-S3-N16R8 DevKit |
| 麦克风 | INMP441 |
| I2S 输入 | 16 kHz, 2ch, 32-bit |
| 应用输入 | 16 kHz, mono, int16 |
| 推理窗口 | 1 秒 |
| 窗口步进 | 250 ms |
| 采集缓冲 | 32,000 samples，约 2 秒 |
| 采集线程优先级 | 140 |
| 主任务优先级 | 100 |

一次 profile 观测中的典型处理耗时：

| 阶段 | 典型耗时 |
| --- | ---: |
| 复制/统计 | 0 - 10 ms |
| 特征提取 | 60 - 70 ms |
| TFLite Micro 推理 | 350 - 360 ms |
| 日志/UI/检测 | 0 - 10 ms |
| 单窗口总处理 | 420 - 430 ms |

延迟解释：

- `audio_event` 每次使用最新 1 秒音频窗口进行推理，因此事件需要先进入 1 秒窗口。
- 单窗口处理耗时约 0.42 秒。
- 告警默认需要连续 2 次命中；在 250 ms hop 下，理想情况下第二次命中会在下一窗口触发。
- 因此真实告警延迟由“事件在 1 秒窗口中的位置 + 处理耗时 + 连续命中策略”共同决定。

正式演示或提交前，建议使用固定脚本记录至少 3 次 profile，并报告平均值、最大值和最小值。

## 端侧演示观测

`logs/演示日志.md` 记录了与演示视频匹配的一段串口日志。该日志展示了：

- INMP441 采集链路可输出非零 PCM。
- OLED 初始化成功。
- 咳嗽事件可以连续命中并触发 `[ALERT] *** cough detected ***`。
- 敲门事件在若干窗口中产生 `knock` 最高概率，但概率分布比咳嗽更分散。

该日志用于演示复核，不等价于严格统计测试集。误报/漏报统计仍以离线测试集和后续固定端侧
测试脚本为准。

## 已知限制

- 离线测试集和 INMP441 真机采集域不完全一致，真实场景下可能存在域偏移。
- 敲门事件的声学形态受门板、距离、敲击力度和安装位置影响较大，需要按现场重新校准阈值。
- ESC-50 和 FSD50K 的部分数据许可包含非商业限制，商业使用前需要重新审查数据来源。
- 当前端侧延迟数据为基础观测值，不是完整 benchmark。

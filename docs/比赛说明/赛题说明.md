一、赛题设计

参赛团队需基于单片机平台（如 DshanPixVela-DevKit V1）与数字麦克风，构建一个本地音频事件检测与告警系统。
赛题仓库

https://www.gitlink.org.cn/openvela
初赛部分目标：

完成离线本地可运行的音频事件检测系统。

任务：
1. 离线本地闭环：完成采集 → 预处理/特征提取 → 模型识别 → 输出/告警（LED/蜂鸣器/屏幕/串口等）全流程在端侧完成；结果可验证、可重复运行。
2. 基础类别覆盖：至少支持 2 类音频事件（如玻璃破碎、咳嗽），提供事件定义与触发口径说明。
3. 可复现与工程化：提供清晰的运行/部署说明，一键运行方式，具备基本异常处理。

初赛交付物：代码仓库、可复现文档、运行演示（视频/日志）。
复赛部分目标：

在初赛基础上进行优化与拓展，从以下任务中自由选做，完成越多、质量越高，得分越高。

1. 类别扩展：增加 1-2 类新事件识别（如婴儿哭声、狗叫、敲门声等），给出对比数据。
2. 鲁棒性提升：提升在噪声环境、不同距离条件下的识别稳定性，给出对比数据。
3. 模型优化：量化/特征优化等降低模型体积与推理延迟，提供优化前后对比。
4. 低功耗策略：唤醒策略、采样窗口策略等，有功耗数据或对比。
5. 远程告警上报：通过 MQTT/HTTP 将告警事件上报到上位机或手机端。
6. 语音关键词识别：实现对 2-3 个自定义关键词的本地识别（本项目选择 `yes`、`no`、`stop`）。
7. 开发板适配（加分项）：自行选择开发板适配 openvela，在真实硬件上运行并演示。适配代码需提交至代码仓库，附适配说明文档。成功适配并提交可获得额外加分。

复赛交付物：代码仓库、复赛增量说明文档、演示视频/日志。

四、高分要点与证据要求

以下内容是围绕上述评分项整理的报告、测试和演示重点。核心原则是：**用真实、可复现的测量数据支撑结论，
并清楚区分训练/测试集结果、真机结果和后续计划。**

| 方向 | 为什么重要 | 最低应提供的证据 | 建议加强项 |
| --- | --- | --- | --- |
| 性能数据 | 初赛“文档与性能数据”占 20%，延迟、误报率、漏报率是可验证性能的基础 | 真机延迟（P50/mean/P95）、测试样本数、误报/漏报定义和原始日志 | 同时给出 reference/优化后、端到端/纯推理两种口径，注明板卡、频率、模型和输入条件 |
| 鲁棒性 | 不同 SNR、距离、环境噪声下的对比最能说明系统不是只适用于单一录音 | 固定测试协议、每组样本数、准确率/FAR/MISS 表 | 绘制 SNR/距离/场景与准确率、FAR、MISS 的对比图；保留未参与训练的真实录音 |
| INT8 量化 | 量化/模型优化是复赛的重要可选方向，必须同时说明体积和精度代价 | float 与 INT8 的模型大小、准确率、量化校准方法 | 增加真机时延、Arena 和 Flash 占用，并说明输出一致性或允许误差 |
| 泛化验证 | 复赛“现场/统一用例表现”占 25%；只在训练集或同源测试集上好看不能证明泛化能力 | 训练集之外的测试集、采集环境、数据划分和指标 | 使用不同设备、距离、说话人/声源、噪声和现场录音，单独报告其结果，避免将其混入训练集指标 |
| 开发板适配 | 真机适配 openvela 是明确加分项，同时体现工程创新 | board 代码、defconfig、构建/烧录步骤、真实硬件演示和适配说明 | 若完成 USB UAC 音频设备适配，应单列驱动/板级改动、枚举与录音日志、兼容性矩阵和演示；这可增强创新性，但最终加分以赛事评审为准 |

### 4.1 初赛性能数据的最小报告模板

| 指标 | 必须说明的口径 |
| --- | --- |
| 延迟 | 采集/特征/推理/总处理的计时边界、P50/mean/P95、样本数、板卡与 CPU 频率 |
| 误报率（FAR） | 什么样的非目标片段算误报、总时长或总窗口数、阈值与冷却时间 |
| 漏报率（MISS） | 什么样的标注事件算一次目标、命中时间容忍范围、漏检数量和总事件数 |
| 资源占用 | 模型 Flash 大小、Tensor Arena 实际使用、资源分区与 RAM 约束 |
| 稳定性 | 连续运行时长/窗口数、是否重启、panic、音频错误或窗口积压 |

所有图表应能追溯到原始 WAV、事件标注、固件 revision、完整构建配置和串口日志；单次演示截图不能替代
统计数据。

### 4.2 复赛泛化与鲁棒性建议

测试集必须与训练集分离。推荐至少按以下维度建立矩阵，并在每格中记录事件数、FAR、MISS、延迟和失败样例：

```text
声源距离：近 / 中 / 远
噪声强度：安静 / 中等噪声 / 强噪声（记录 SNR）
环境：室内安静 / 室内混响 / 室外或背景人声
输入方式：训练集外 WAV / 实时麦克风 / 现场统一用例
```

报告中应单独展示“训练内测试”和“训练外泛化”结果。若泛化结果下降，应如实说明数据分布差异和改进计划；
这比只展示训练集附近的数据更有说服力。

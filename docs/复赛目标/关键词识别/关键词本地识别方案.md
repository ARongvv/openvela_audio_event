# 本地关键词识别扩展方案

> 状态：方案设计，尚未实现。  
> 目标：在现有 `audio_event` 的本地音频事件检测能力上，增加 2–3 个自定义中文关键词的离线识别能力。

## 1. 目标与边界

本方案实现的是小词表关键词唤醒（Keyword Spotting, KWS），而不是通用语音识别：设备只判断预定义短语是否出现，不输出完整转写文本。

首版建议支持以下紧急求助类关键词：

| 内部标签 | 用户可见名称 | 可接受说法 |
| --- | --- | --- |
| `yes` | yes | 英文词 `yes` 的不同说话人、音量、语速和口音发音 |
| `no` | no | 英文词 `no` 的不同说话人、音量、语速和口音发音 |
| `stop` | stop | 英文词 `stop` 的不同说话人、音量、语速和口音发音 |

内部标签与用户可见名称统一使用 ASCII 英文，避免模型元数据、C 源码和 OLED 字体的编码问题。首版只识别精确定义的 `yes`、`no`、`stop`；`yeah`、`nope`、中文“是/否/停止”等同义词不属于首版命中范围，除非后续明确加入训练和验收口径。

关键词触发应满足以下边界：

- 关键词必须由人声清晰说出；系统不承诺理解任意句子。
- 普通对话、其他中文词、电视人声、音乐、咳嗽、敲门和环境噪声均不应触发关键词告警。
- 本功能必须全程离线运行，不依赖云端 ASR、网络或手机。
- 当前 `knock`、`cough` 本地事件检测能力应继续可用，不能因关键词扩展而退化。

## 2. 当前基线和设计约束

当前部署路径为 `ESP32-S3-N16R8 DevKit + INMP441 + OLED`，其模型为四类 INT8 模型：

```text
knock, cough, background, silence
```

模型输入为 16 kHz、1 秒、单声道 PCM，特征形状为 `49 x 40 x 3`，当前模型文件为 11,984 bytes。真机基础观测中，一次完整窗口处理约为 420–430 ms，其中 TFLite Micro 推理约为 350–360 ms。详细口径见[性能与评估.md](../../项目基线/性能与评估.md)。

因此，首版不采用“在现有事件模型之外串行再跑一个关键词模型”的双模型常驻方案：这会近似增加一次完整推理的负载，使现有的实时性进一步恶化。

## 3. 推荐架构：统一多类别模型

推荐将关键词与既有目标事件合并到一份模型中，仅运行一次特征提取与一次推理：

```text
INMP441
  -> 16 kHz mono PCM 环形缓冲区
  -> 1 秒滑动窗口 / log-mel 特征
  -> 一份 INT8 TFLite Micro 多类别模型
  -> 类别专属判决策略
  -> OLED、串口和本地告警
```

首版统一模型的类别定义为：

| ID | 类别 | 是否告警 | 说明 |
| ---: | --- | --- | --- |
| 0 | `knock` | 是 | 既有敲击/敲门事件 |
| 1 | `cough` | 是 | 既有咳嗽事件 |
| 2 | `yes` | 是 | 自定义关键词 `yes` |
| 3 | `no` | 是 | 自定义关键词 `no` |
| 4 | `stop` | 是 | 自定义关键词 `stop` |
| 5 | `background` | 否 | 环境声、其他人声、未知词及干扰声 |
| 6 | `silence` | 否 | 静音或接近噪声地板的输入 |

`background` 不只是无声背景。对关键词功能而言，它必须包含足量的非关键词人声；否则模型可能把“检测到人声”错误学习成“检测到关键词”。

### 3.1 为什么不先做独立关键词应用

独立的 `keyword_spotter` 可作为数据和模型的验证原型，但不宜直接作为最终常驻架构。

| 方案 | 优点 | 风险/代价 |
| --- | --- | --- |
| 独立关键词应用 | 改动小；可单独验证数据与模型 | 与 `audio_event` 不能同时低成本运行；展示割裂 |
| 双模型并行 | 两份模型互不影响 | 当前板端一次推理已较慢；延迟、RAM 和调度风险高 |
| **统一多类别模型** | 一次推理覆盖事件与关键词；演示完整 | 需要重训；固件要从固定四类改为可扩展类别 |

实施时可先用独立原型验证关键词训练集和板端效果；原型达标后，再导出统一模型并替换主应用模型。

## 4. 数据集设计与清洗

### 4.1 数据目录

训练数据可沿用现有训练脚本的目录约定：

```text
datasets_keyword/
├── yes/
├── no/
├── stop/
├── knock/
├── cough/
└── background/
```

`silence` 继续由训练脚本生成。每个文件应规范为 16 kHz、16-bit、单声道 WAV；训练时统一裁剪或补零为 1 秒。

### 4.2 最低采集要求

每个关键词至少采集 40 位说话人、每位 15–30 条有效发音，目标为每词 600–1200 条有效正样本。样本应覆盖：

- 不同性别、年龄段、音量、语速和普通话口音；
- 不同英语口音、语速、重音、音量与连读方式；
- 近讲、约 1 m 和约 3 m 距离；
- 安静、谈话、电视/音乐、风扇/空调等背景；
- 至少 30% 采用 ESP32-S3 + INMP441 实录，以降低桌面录音与板端之间的域偏移。

关键词正样本外，`background` 至少应包含同量级、最好两倍以上的负样本，尤其是：其他中文短词、连续对话、发音相近词、电视人声、音乐、咳嗽、敲门和室内生活噪声。

### 4.3 清洗原则

为训练样本保留以下元数据：原始录音 ID、说话人 ID、录制会话 ID、距离、环境、设备、关键词和人工审核结果。

应剔除或移入 `rejected/` 的样本包括：

- 标签错误、目标词不完整或无法听清；
- 关键词被其他人声、音乐或强噪声掩盖；
- 长时间静音、严重削波、录制中断或格式异常；
- 同一原始录音产生的高度重叠近重复切片。

现有 `datasets_segments/review_audio.py` 可用于人工试听、保留、跳过和移入 `rejected/`。`rejected/` 应保留以便审计，但训练输入只扫描各正式类别目录。

### 4.4 防止数据泄漏

训练、验证和测试必须按“说话人 + 原始录音/会话”分组切分，而不是对 1 秒切片随机切分。相邻或重叠切片若分散到训练集和测试集，会造成指标虚高。

建议划分：训练集 70%，验证集 15%，测试集 15%；测试集中的说话人和录制会话均不得出现在训练集。

## 5. 模型和特征契约

### 5.1 首版模型

首版优先沿用当前 DS-CNN + INT8 TFLite Micro 训练与部署链路。输入仍使用：

| 项目 | 值 |
| --- | --- |
| 采样率 | 16 kHz |
| 窗口时长 | 1 秒，16,000 个采样点 |
| 分帧 | 30 ms 窗，20 ms 步长 |
| FFT | 512 点 |
| Mel | 40 bins，125–7500 Hz |
| 候选特征 | log-mel；是否保留 delta/delta-delta 由对比实验决定 |
| 量化 | 全 INT8 输入/输出 |

`yes`、`no` 和 `stop` 本身通常可放入 1 秒窗口。训练中仍应随机平移、裁剪和补零，避免模型只学习固定位置；若实测有大量首尾截断，再评估扩大窗口。扩展窗口会改变帧数、特征维度和模型输入，不能与 1 秒模型混用。

### 5.2 必须先完成的数值验证

重新训练或部署关键词模型前，必须导出黄金 PCM、浮点特征、量化 INT8 特征和桌面 TFLite 输出，并在固件侧逐项比对。训练端和固件端的窗函数、Mel 矩阵、对数缩放、delta 算法、展平顺序及量化参数必须一致。

验收条件：同一黄金样本的 Python 与 C 特征误差在预先定义的容差内，桌面 TFLite 与板端 TFLite Micro 的最高类别一致。未通过这一验收前，不以板端分类结果判断关键词模型优劣。

### 5.3 训练策略

- 对关键词正样本做随机平移、增益变化和背景混音。
- 不从测试集抽取量化 representative dataset。
- 比较 mel-only 与 `mel + delta + delta-delta` 的离线效果、模型大小、Tensor Arena 和真机耗时；不预设三通道一定更优。
- 先以当前 small 模型量级为资源基线；medium/large 只能在完成真机 Flash、Arena、延迟测量后作为候选。
- 每轮导出 `metadata.json`、类别顺序、模型 SHA-256、混淆矩阵、阈值扫描和数据划分清单。

## 6. 固件改造方案

### 6.1 配置和模型接口

当前固件将类别数固定为 4、目标事件固定为 `knock/cough`、阈值数组固定为 2 项。关键词扩展应改为以下原则：

1. 类别顺序以随模型提交的 `labels.txt`/`metadata.json` 为唯一事实来源。
2. 将 `AUDIO_EVENT_CLASS_COUNT`、类别名、是否告警和每类阈值集中定义，禁止在 UI、检测器和主循环中各自维护一份顺序。
3. 初始化时校验模型输出元素数、类别表长度和量化参数；不一致则拒绝运行。
4. 重新生成 `model.cc`、`model.h` 和元数据，禁止只替换 `.tflite` 而不更新嵌入数组。

### 6.2 判决和告警策略

既有冲击类声音可保留“连续两窗命中 + 冷却”的策略。关键词较短，首版建议使用每类独立阈值、单窗高置信触发和冷却：

```text
best_class 为关键词
且 probability >= keyword_threshold[class]
且不在该类冷却期
    -> 立即告警，记录类别、置信度和时间戳
```

理由是当前真机实际处理周期受特征提取和推理耗时限制，不能假设每 250 ms 都会完成一次新推理；强制连续两窗可能漏掉短促关键词。阈值应由独立测试集和真机实录扫描确定，首版不得把 0.75 当作未经验证的固定值。

关键词告警应至少输出：

```text
[ALERT] keyword=yes confidence=NNN/1000 timestamp=...ms
```

并在 OLED 上显示最新关键词和冷却状态。告警输出失败不得阻塞采集线程或后续推理。

## 7. 评估和验收

### 7.1 离线评估

除总 Accuracy 外，必须按每个关键词报告：

| 指标 | 说明 |
| --- | --- |
| Precision / Recall / F1 | 每个关键词独立统计 |
| 漏检率 | 关键词存在但未触发的比例 |
| 误唤醒率 | 非关键词样本被判为该关键词的比例 |
| 混淆矩阵 | 重点观察关键词之间及关键词/背景之间的混淆 |
| 未见说话人结果 | 只在训练未出现的说话人上统计 |

### 7.2 真机评估

在 ESP32-S3 + INMP441 上，以固定脚本测试安静、噪声、近距离和远距离场景。至少记录：

- 每词的成功次数/总次数和误唤醒次数；
- 从发音开始到本地告警的端到端延迟；
- 特征提取、推理和总处理耗时的均值、最大值、最小值；
- 模型 Flash 大小、Tensor Arena 实测使用量和应用 RAM；
- 至少 30 分钟连续运行结果及异常恢复情况。

严禁把模拟器数据当作 MCU 性能、功耗或真机识别效果数据。关键词准确率、误唤醒率和端到端延迟的最终阈值在完成数据采集后确定。

## 8. 分阶段实施与完成定义

| 阶段 | 主要工作 | 完成标志 |
| --- | --- | --- |
| K0 | 冻结关键词语义、数据口径和划分规则 | 关键词/变体/负样本边界写入数据说明 |
| K1 | 采集、切片、人工清洗和分组切分 | 可追溯 manifest；测试说话人未泄漏到训练集 |
| K2 | 完成训练端/固件端黄金特征验证 | Python、桌面 TFLite、TFLM 分类一致 |
| K3 | 训练并筛选 INT8 候选模型 | 获得离线指标、模型体积与阈值扫描结果 |
| K4 | 扩展主应用类别表、检测器和 OLED | 统一模型可在真机启动和输出全部类别 |
| K5 | 真机场景测试、性能和稳定性测试 | 固定用例、日志和演示视频齐全 |

本功能只有同时满足以下条件才算完成：

- [ ] 至少识别 2 个已定义关键词，且全程离线运行。
- [ ] 非关键词人声和常见环境声有独立负样本与误唤醒测试。
- [ ] 数据按说话人和会话切分，测试集不泄漏。
- [ ] 训练、固件特征和量化通过黄金向量验证。
- [ ] 真机上有每词成功率、误唤醒、延迟、Flash、RAM 和连续运行记录。
- [ ] 当前 `knock`、`cough` 的固定回归用例不退化。
- [ ] 模型、标签、元数据、训练命令和许可证信息可复现、可溯源。

## 9. 主要风险与应对

| 风险 | 后果 | 应对 |
| --- | --- | --- |
| 数据只来自少量说话人 | 未见说话人漏检 | 按说话人采集并做未见说话人测试 |
| 非关键词人声不足 | 现场误唤醒 | 扩充其他中文词、对话、电视和音乐负样本 |
| 重叠切片随机分组 | 离线指标虚高 | 按原始录音/说话人分组切分 |
| 特征契约漂移 | 板端输出失真 | 使用黄金 PCM/特征/INT8 向量回归 |
| 类别数增加导致资源超限 | `AllocateTensors()` 失败或延迟变差 | 以 small 为基线，真机测量后再选择模型规模 |
| 关键词采用两窗确认 | 短词漏检 | 使用单窗高阈值、冷却与负样本抑制误报 |
| OLED 无中文字库 | 显示缺字 | 内部和 OLED 使用拼音，串口/文档显示中文 |

# 音频事件识别鲁棒性提升方案

> 状态：方案设计，尚未实施。  
> 目标：提升 `audio_event` 在噪声环境和不同声源距离下对目标事件的识别稳定性，并以可复现的真机对比数据证明改进效果。

## 1. 目标与原则

本方案面向当前 `ESP32-S3-N16R8 DevKit + INMP441` 真机路径，优先提升已有 `knock`、`cough` 两类事件在真实采集域中的表现。后续增加关键词时，沿用同一套数据、测试和评估方法。

鲁棒性不以单一离线 Accuracy 定义，而是同时关注：

- 不同距离、不同环境下的事件级召回率；
- 非目标声和连续背景中的误触发率；
- 从声音开始到本地告警的端到端延迟；
- 模型大小、Tensor Arena、处理耗时和稳定性不超过目标板资源边界。

实施遵循以下原则：

1. **先冻结基线和测试集，再优化。** 不能用调参后的同一批数据证明改进。
2. **真机数据与公开数据分开报告。** 模拟器和桌面测试不能替代目标板效果。
3. **每次只改变一类因素。** 数据、特征、模型和阈值分别进行消融比较。
4. **训练、验证、测试按原始录音和会话分组。** 相邻/重叠切片不得跨集合，防止数据泄漏。

## 2. 当前基线和约束

当前部署模型为 small INT8 DS-CNN，类别为：

```text
knock, cough, background, silence
```

模型使用 16 kHz、1 秒、单声道 PCM 和 `49 x 40 x 3` log-mel 特征。模型文件为 11,984 bytes，Tensor Arena 配置 65,536 bytes、已观测使用 22,708 bytes。一次真机窗口处理基础观测约为 420–430 ms，其中模型推理约为 350–360 ms。详细数据见[性能与评估.md](../项目基线/性能与评估.md)。

当前真机阈值为：

| 类别 | 阈值 | 连续命中 | 说明 |
| --- | ---: | ---: | --- |
| `knock` | 380‰ | 2 窗 | 板端实录中置信度较分散 |
| `cough` | 750‰ | 2 窗 | 保持较高阈值以抑制误报 |

当前处理耗时已经高于配置的 250 ms hop。因此，不能仅通过提高连续命中次数降低误报；这会增加实际告警延迟并可能导致短促事件漏检。所有时序策略必须在真机上重新测量。

## 3. 测试基线：固定真机用例

### 3.1 测试矩阵

先使用不做任何训练和阈值修改的当前固件，运行以下固定用例并保存为 Baseline：

| 维度 | 首版档位 | 记录要求 |
| --- | --- | --- |
| 距离 | 0.5 m、1 m、3 m | 麦克风到声源的实际距离 |
| 环境 | 安静、风扇/空调、谈话、音乐/电视 | 背景类型与声级/SNR |
| 场地 | 至少 2 个房间 | 房间类型、开门窗状态、混响特征 |
| 目标事件 | `knock`、`cough` | 事件类型、发生时间和次数 |
| 正样本次数 | 每个“事件 × 距离 × 环境”至少 15 次 | 成功/漏检/重复触发 |
| 负样本 | 每种环境至少 10 分钟 | 无目标事件时的告警次数 |

若条件允许，应在麦克风位置使用声级计记录 dBA；最低限度可使用同一台手机、同一声级应用和同一摆位作相对记录。仅记录扬声器音量百分比不足以复现声学条件。

### 3.2 固定摆位和流程

```text
扬声器/事件声源  ---- 指定距离 ----  INMP441
                                      |
                                      +-- ESP32-S3 DevKit
```

- 固定麦克风朝向、高度和与反射面的距离；测试期间不得随意移动。
- 回放测试音源时，使用相同 WAV、播放器和音量档位；人工咳嗽/敲门时记录执行者和动作方式。
- 每次测试前运行 `audio_test` 检查采集并记录 PCM 最大值、RMS、零样本比例和削波情况。
- 使用 `audio_event --audio-stats --profile --no-oled` 记录时间戳、概率和耗时；正式演示再打开 OLED。
- 用人工标注或播放脚本记录每次真实事件的开始时间，便于计算事件级结果和端到端延迟。

### 3.3 事件级判定口径

以真实事件发生时刻为中心定义可接受触发窗口；首版建议从事件开始后 2 秒内出现对应告警即为成功，最终窗口根据实测延迟冻结。

| 结果 | 定义 |
| --- | --- |
| TP | 真实目标事件后，在可接受窗口内触发正确类别 |
| FN | 真实目标事件后未触发正确类别 |
| FP | 无真实目标事件的时间段触发任意目标告警 |
| 重复告警 | 同一真实事件在冷却期后仍产生额外告警，单独统计 |

计算指标：

```text
Recall    = TP / (TP + FN)
Precision = TP / (TP + FP)
F1        = 2 * Precision * Recall / (Precision + Recall)
误触发率  = FP / 无目标事件观察时长（次/分钟或次/小时）
```

不得使用逐窗口分类 Accuracy 替代上述事件级指标。

## 4. 数据域适配与清洗

### 4.1 优先补充的真实数据

公开音频数据与 INMP441 板端录音在频响、增益、混响和背景噪声上存在域偏移。应使用 `audio_record` 采集并保留以下真实板端数据：

- `knock`：不同门板/桌面材料、力度、敲击位置和执行者；
- `cough`：不同说话人、咳嗽类型、音量和朝向；
- `background`：谈话、电视、音乐、风扇、空调、键盘、脚步、室内安静和室外传入噪声；
- 各事件在 0.5 m、1 m、3 m 以及至少两个房间的录音。

优先将实录数据用于独立测试集和校准集；在冻结测试集后，剩余实录数据才可加入训练集。

### 4.2 数据清洗和溯源

每段录音至少记录：

```text
recording_id, source_id, room_id, device_id, event_class,
distance_m, noise_type, noise_level, start_time_ms, review_status
```

以下样本不应作为正样本训练：标签错误、事件不可辨认、严重削波、异常静音、录制中断、目标事件被其他人声/音乐掩盖，以及与同一原始录音高度重叠的重复切片。

人工清洗可复用 `datasets_segments/review_audio.py`。错标样本移入 `rejected/` 保留审计信息，不参与训练。

### 4.3 防数据泄漏

训练、验证和测试必须以 `source_id`/`recording_id` 为最小分组单位，并且尽可能按录制会话或执行者分组。不能将同一原始长录音生成的相邻 1 秒窗口随机分散到不同集合。

建议比例为训练集 70%、验证集 15%、测试集 15%；用于最终对比表的真机固定用例必须完全不参与训练、阈值扫描或量化校准。

## 5. 优化路线和消融实验

所有候选均以同一份冻结真机测试集比较；每轮记录模型哈希、训练命令、数据版本、阈值和构建版本。

| 编号 | 改动 | 目的 | 必须保持不变的对照 |
| --- | --- | --- | --- |
| B0 | 当前 small 模型与当前板端阈值 | 建立 Baseline | 固定测试集、板卡、摆位和日志格式 |
| B1 | 增加 INMP441 实录训练数据 | 缩小设备/房间域偏移 | 模型结构和特征 |
| B2 | B1 + 噪声混音、随机增益、时间平移 | 提升噪声和音量变化适应性 | 模型结构、测试集 |
| B3 | B2 + 候选特征前端 | 比较 mel-only、delta 或 PCEN | 训练数据划分、模型资源预算 |
| B4 | B2/B3 最优模型 + 每类阈值/时序扫描 | 控制误触发与漏检平衡 | 模型权重和冻结测试集 |

### 5.1 训练增强

在 B2 中，对训练集中的正样本进行：

- 随机时间平移，使事件不会总位于 1 秒窗口中心；
- 随机增益变化，模拟近距离、远距离和不同说话音量；
- 与真实 INMP441 背景按多个 SNR 混音，建议比较 5、10、15、20 dB；
- 保留部分纯净样本，避免模型只适应加噪后的分布。

验证集和测试集不得使用随机增强。噪声来源、混音比例和随机种子必须保存到训练记录。

### 5.2 特征和模型候选

首轮保持模型规模接近当前 small 模型，先确认数据域适配的收益。若需要比较特征前端，可测试：

- 现有 log-mel + delta/delta-delta；
- log-mel only，降低输入特征维度和前端计算量；
- PCEN，作为非平稳背景下的候选归一化特征。

任何新前端都必须同时在训练端和固件端实现，并完成黄金 PCM、浮点特征、INT8 输入和 TFLite 输出对齐。不得只在 Python 端启用 PCEN、谱减或 AGC 后直接把原模型部署到固件。

medium/large 模型可作为离线候选，但只有在真机上同时报告 Flash、Tensor Arena、处理耗时和稳定性后，才可称为鲁棒性优化方案。

### 5.3 判决策略校准

保持模型权重不变，使用校准集而非最终测试集扫描：

- 每类独立概率阈值；
- 连续命中次数；
- 冷却时间；
- 重复告警合并窗口。

阈值选择以每类 Recall、误触发率、端到端延迟为依据。对短促事件，增加连续命中次数可能压低误报，也可能增加漏检；必须报告该取舍，不能只展示最优 Recall。

## 6. 采集链路健康检查

模型优化前后均应通过 `audio_test` 和 `audio_record` 检查音频输入：

| 检查项 | 异常含义 | 处理方向 |
| --- | --- | --- |
| 大量 `INT16_MIN/MAX` 或近削波 | 输入饱和 | 调整麦克风安装、增益或 I2S 右移位 |
| RMS 长期接近零 | 接线、slot、位宽或信号问题 | 检查 INMP441 slot 和采样转换 |
| 大量全零样本 | DMA/设备/读取异常 | 优先修复采集链路，不训练补偿模型 |
| 远距离事件低于噪声地板 | 物理 SNR 不足 | 调整摆位、提高有效信噪比或明确能力边界 |

不建议在未验证前加入固定的软件增益或频谱降噪。此类处理会改变模型输入分布，必须纳入训练和黄金特征验证。

## 8. 阶段计划与完成定义

| 阶段 | 工作 | 验收输出 |
| --- | --- | --- |
| R0 | 固定摆位、测试音源、日志格式和事件级口径 | 版本化测试计划与 Baseline 日志 |
| R1 | 采集真实 INMP441 数据、清洗和分组切分 | 可追溯 manifest、冻结测试集 |
| R2 | B1/B2 数据域适配训练 | 离线混淆矩阵和候选模型记录 |
| R3 | 前端/模型候选消融与黄金特征验证 | 特征误差、资源与耗时比较 |
| R4 | 阈值、连续命中、冷却校准 | 校准曲线和最终配置 |
| R5 | 同一真机用例对比和稳定性测试 | 对比表、日志、视频和已知限制 |

本项只有在以下条件同时满足时才算完成：

- [ ] 优化前后在同一冻结真机用例中完成事件级对比。
- [ ] 至少覆盖 0.5 m、1 m、3 m 和两种以上噪声环境。
- [ ] 报告每类召回、误触发率和端到端延迟，而非仅报 Accuracy。
- [ ] 最终测试集未参与训练、阈值选择或量化校准。
- [ ] 新特征/新模型通过训练端与固件端黄金向量验证。
- [ ] 提供模型大小、Tensor Arena、处理耗时和连续运行记录。
- [ ] 当前采集链路无全零、格式错误或未解释的削波问题。

## 9. 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 只用公开数据训练 | 真机域偏移、现场漏检 | 加入 INMP441 实录并独立评测 |
| 重叠切片随机划分 | 指标虚高 | 按原始录音/会话分组 |
| 背景录音不足 | 噪声环境误报 | 按真实场景采集负样本并报告 FP/min |
| 只提高阈值或连续命中 | 看似降误报但漏检和延迟恶化 | 以 Recall、FP/min、延迟共同选参 |
| 模型变大 | 板端内存/时延超限 | small 为基线，所有候选真机实测 |
| 前端与训练不一致 | 板端效果不可解释 | 黄金向量验证作为部署前置条件 |
| 录音削波或信噪比过低 | 学习到错误分布 | 先修复接线、摆位、slot/shift 或安装方式 |

# 音频事件检测低功耗策略方案

> 状态：P1 软件能量门控已完成代码接入，尚未完成 ESP32-S3 真机功耗与识别回归测试。
> 目标：在不破坏本地事件识别可靠性的前提下，降低 `audio_event` 的平均处理负载和能耗，并给出基于同一块真机的可复现功耗对比数据。

## 1. 范围与结论边界

当前系统使用 ESP32-S3、INMP441 数字麦克风和持续 I2S 采集，主链路为：

```text
INMP441/I2S 采集 -> 1 秒窗口 -> log-mel 特征 -> TFLite Micro -> 告警
```

当前基础观测中，单个窗口的特征提取和推理约占 420–430 ms。低功耗首版的重点是减少不必要的特征提取和模型推理次数，而非宣称关闭全部音频硬件。

INMP441 是数字 I2S 麦克风，没有独立的低功耗语音活动检测（VAD）中断输出；只要需要持续监听，就仍需维持麦克风时钟、I2S/DMA 和最低限度的 MCU 处理。因此：

- 软件能量门控可以节省 DSP/TFLM 计算，但不能消除 I2S/麦克风的基础功耗。
- 周期性关闭 I2S 可进一步降低平均功耗，但会产生监听盲区，可能漏掉短促的敲门或咳嗽。
- 所有节能结论必须以实测电流、能量和识别指标共同给出，不能仅以“减少推理次数”替代功耗数据。

## 2. 当前基线

当前部署模型为 small INT8 DS-CNN，输入为 16 kHz、1 秒、单声道 PCM，特征为 `49 x 40 x 3`。模型文件为 11,984 bytes，Tensor Arena 配置 65,536 bytes。当前的处理耗时、阈值和真机配置见[性能与评估.md](../项目基线/性能与评估.md)。

低功耗对比的基线模式定义为 `continuous`：持续 I2S 采集，并按现有窗口/判决逻辑执行完整特征提取和模型推理。所有候选模式与该基线使用相同板卡、固件编译选项、麦克风、供电方式和测试用例。

## 3. 分级策略

### 3.1 P0：连续模式（基线）

```text
每个推理窗口：采集 -> 完整特征 -> TFLM -> 判决
```

P0 不作节能，是识别效果、延迟、推理次数和功耗的对照组。

### 3.2 P1：软件能量门控（首选实现）

持续采集低成本 PCM 块，但先计算 RMS/峰值等轻量能量特征。只有满足活动条件时，才执行完整 1 秒特征提取和 TFLite Micro 推理。

```text
I2S/DMA PCM block
  -> RMS/peak 统计
  -> 能量低于动态门限：跳过 DSP/TFLM，保持监听
  -> 能量高于动态门限：进入 ACTIVE，执行完整分类
  -> ACTIVE 持续一段保持时间后：回到 LISTEN
```

建议状态机：

| 状态 | 行为 | 退出条件 |
| --- | --- | --- |
| `LISTEN` | 每个小 PCM 块仅计算能量统计 | 能量超过门限 |
| `ACTIVE` | 按正常窗口运行特征、模型和检测器 | 连续静音达到保持时长 |
| `COOLDOWN` | 按既有告警冷却逻辑处理 | 冷却结束后回到 `ACTIVE` 或 `LISTEN` |

门限不能仅使用固定 RMS 常量。应维护安静环境噪声地板，使用“噪声地板 + 余量”的动态门限，并设置最小/最大边界：

```text
activity_threshold = clamp(noise_floor_rms * ratio + offset,
                           threshold_min, threshold_max)
```

噪声地板只能在 `LISTEN` 且未发生高能事件时缓慢更新；否则持续音乐或说话会把门限抬高，造成真实事件漏检。

P1 的优点是改动集中、无 I2S 监听盲区，适合作为首个可提交方案。它主要节省静音和低噪环境中的计算功耗；在持续谈话或音乐环境，门控可能长期打开，节能收益会下降，这必须如实报告。

### 3.3 P2：自适应推理窗口

在 `LISTEN` 状态不执行完整模型；进入 `ACTIVE` 后以正常间隔推理。可以进一步定义两档活跃策略：

| 模式 | 触发条件 | 完整推理策略 | 取舍 |
| --- | --- | --- | --- |
| `quiet` | 能量长期低 | 只做轻量能量检测 | 最省计算，但依赖门控召回 |
| `active` | 能量超过门限 | 使用正常滑窗推理 | 保持事件识别能力 |
| `busy`（候选） | 持续高背景噪声 | 降低非关键窗口频率，保留定期探测 | 可能降低误报，也可能增加延迟 |

`busy` 只能在固定真机用例上证明不降低目标事件召回后启用。不能简单把推理周期拉长后只比较平均功耗。

### 3.4 P3：I2S 占空监听（高级候选）

周期性启动 I2S、采集短块、停止 I2S，只有检测到活动时才进入持续采集。这一方案可能降低 I2S/麦克风相关平均功耗，但会产生采样盲区：

```text
采集 100 ms -> 休眠 100 ms -> 采集 100 ms -> ...
```

短促事件可能完全落在休眠期，且 I2S 重启、缓冲区稳定和时钟建立本身需要验证。P3 不作为首版承诺；只有 P1/P2 通过识别和功耗对比后才评估。

## 4. 固件实现边界

### 4.1 推荐模块划分

```text
audio_capture
  -> power_gate（PCM 块能量、噪声地板、状态机）
  -> feature_extract（仅 ACTIVE 调用）
  -> event_classifier（仅 ACTIVE 调用）
  -> event_detector / event_alert
```

`power_gate` 应只接收 PCM 块和时间戳，对外提供“本窗口是否需要完整推理”的判断。它不应直接操作 TFLite、OLED 或网络，使其可用固定 PCM 单独测试。

### 4.2 建议配置项

配置项名称在实现时确定，首版建议覆盖：

| 配置 | 示例语义 |
| --- | --- |
| `POWER_MODE` | `continuous` / `energy_gate` |
| `ENERGY_BLOCK_MS` | 能量统计块大小，例如 20–100 ms |
| `ENERGY_THRESHOLD_MIN` | 门限最低值，防止噪声地板过低 |
| `ENERGY_MARGIN` | 相对噪声地板的活动余量 |
| `NOISE_FLOOR_ALPHA` | 噪声地板缓慢更新系数 |
| `ACTIVE_HOLD_MS` | 最后一次活动后的持续完整推理时间 |
| `MAX_SILENT_PROBE_MS` | 长静音时的最大探测间隔（如启用） |

所有参数必须打印到启动日志并记录在测试报告中。参数不是跨房间通用的事实，应允许按场景重新校准。

### 4.3 安全行为

- 门控模块异常、未校准或检测到无效 PCM 时，回退到 `continuous`，不能静默跳过全部推理。
- 不能让低功耗路径阻塞采集线程或破坏现有环形缓冲区。
- 告警后应保留一段 `ACTIVE_HOLD_MS`，避免事件尾部被立即忽略。
- 不加入未经训练验证的固定增益、降噪或频谱处理；它们会改变模型输入分布。

### 4.4 P1 实施总结（2026-07）

P1 已按“持续采集、仅节流 DSP/TFLM”的边界接入，未停止 INMP441、I2S 或 DMA。新增模块及改动如下：

| 文件 | 实施内容 |
| --- | --- |
| `app/audio_event/power/power_gate.h` | 定义门控状态、统计快照和 `init/process/take_inference` 接口。 |
| `app/audio_event/power/power_gate.c` | 对每个 PCM 块计算整数 RMS 与绝对峰值；完成启动校准、动态门限、ACTIVE 保持、静音强制探测和统计。 |
| `app/audio_event/main/audio_event_main.c` | 设备采集线程在写入环形缓冲后更新门控；主线程仅在门控允许时调用 `process_window()`。文件回放路径使用同一门控逻辑，便于冻结 PCM 回归。 |
| `app/audio_event/detector/event_detector.[ch]` | 新增 `event_detector_reset_candidate()`，在门控跳过窗口时清空连续命中候选，但保留既有 cooldown。 |
| `app/audio_event/Kconfig` | 提供 P0/P1 选择和校准、门限、噪声地板、保持、强制探测参数。 |
| `app/audio_event/CMakeLists.txt`、`Makefile` | 将 `power/power_gate.c` 加入两种构建方式。 |
| `board/esp32s3-devkit/configs/audio_event/defconfig` | 编入 P1 门控实现；默认连续推理，真机标定时以 `--power-gate` 显式开启。 |

实现后的数据路径为：

```text
capture_thread_main()
  -> audio_capture_read(PCM block)
  -> 写入 2 秒 ring buffer
  -> power_gate_process(RMS + peak, 音频样本时间)
  -> semaphore 唤醒主线程

run_device_loop() / 文件回放循环
  -> 复制最新 1 秒窗口
  -> power_gate_take_inference()
      -> true：feature_extract -> TFLM -> event_detector
      -> false：跳过 DSP/TFLM，并 reset_candidate
```

`ACTIVE` 由任一条件进入：

```text
block_rms  >= dynamic_rms_threshold
or
block_peak >= dynamic_peak_threshold
```

每次高能块都会将 `ACTIVE` 延长 `ACTIVE_HOLD_MS`。在 `LISTEN` 中，噪声地板只对未触发活动的块作缓慢 IIR 更新；高能块和 ACTIVE 期间不会抬高噪声地板。初始校准期间仍运行完整推理，作为门控未就绪的失效安全回退。

当前首轮默认参数是待真机标定的起点，而不是跨环境通用结论：

| 参数 | 当前值 | 说明 |
| --- | ---: | --- |
| `CALIBRATION_MS` | 2000 ms | 启动时收集噪声地板，同时保持完整推理。 |
| `RMS_RATIO_PERMILLE` | 2000 | 动态 RMS 门限为噪声地板的 2 倍再加偏置。 |
| `RMS_OFFSET` | 200 | 防止安静环境门限过低。 |
| `RMS_MIN / RMS_MAX` | 600 / 6000 | 动态 RMS 门限的钳位范围。 |
| `PEAK_RATIO_PERMILLE` | 2500 | peak 门限相对 RMS 门限的倍率。 |
| `PEAK_MIN` | 1800 | 保留 knock 等短促瞬态的触发机会。 |
| `NOISE_ALPHA_PERMILLE` | 20 | 仅对安静块进行缓慢噪声地板更新。 |
| `ACTIVE_HOLD_MS` | 1500 ms | 确保 cough/knock 的后续窗口仍获得完整推理，并满足连续命中检测。 |
| `FORCE_PROBE_MS` | 5000 ms | 长静音时最多每 5 秒运行一次完整探测；设为 0 可关闭。 |

启动和退出日志提供可复现证据：

```text
[power_gate] compiled=1 runtime=on mode=energy_gate ...
[power_gate] source=device ... blocks=... infer=... skip=...
```

其中 `infer`/`skip` 是门控在推理窗口上的放行/跳过计数，可直接用于计算完整推理次数下降比例。它们不是功耗数据，仍须按第 5 节实际测量电流和能量。

生产 defconfig 仍选择默认模式；对于冻结 WAV 的 P0/P1 公平对照，建议使用同一份
`CONFIG_EXAMPLES_AUDIO_EVENT_POWER_ENERGY_GATE=y` 固件，通过运行时开关切换：

```sh
# P0：连续推理。完全绕过 RMS/peak 计算，每一个 hop 均执行特征和模型。
audio_event --file /data/combined_A_pure.wav --profile --no-oled --no-power-gate

# P1：当前能量门控。默认关闭，必须显式传入 --power-gate。
audio_event --file /data/combined_A_pure.wav --profile --no-oled --power-gate
```

启动日志会记录 `compiled`、`runtime` 和实际 `mode`，退出统计中的 `infer/skip` 用于确认
门控确实生效。`--power-gate` 只可用于编译时已启用
`CONFIG_EXAMPLES_AUDIO_EVENT_POWER_ENERGY_GATE=y` 的固件；在不含该功能的 P0 固件上会明确报错。
未传参数时，门控能力已编入固件但默认关闭，等价于连续 P0；`--no-power-gate` 则可作为
日志中的显式 P0 标记。P0/P1 必须使用相同模型、阈值、CPU 频率、OLED/Wi-Fi/串口状态和音频用例。

## 5. 功耗测量方案

### 5.1 测量条件

功耗比较必须满足：

- 同一块 ESP32-S3、同一 INMP441、相同 OLED/Wi-Fi/串口状态；
- 相同固件编译选项、CPU 频率和供电电压；
- 明确测量点：USB 5 V 输入或板载 3.3 V 支路，不能混用；
- 使用 USB 功率计、INA219/INA226、电流探头或等效设备；记录设备型号、采样率和精度；
- 每个场景至少重复 3 次，记录平均值和波动范围。

首版测量场景：

| 场景 | 时长 | 目的 |
| --- | ---: | --- |
| 安静/无事件 | 10 分钟 | 评估 P1 的主要节能收益 |
| 风扇或空调 | 10 分钟 | 评估中低噪声下门控是否稳定 |
| 谈话/音乐 | 10 分钟 | 评估持续活动导致的最差节能情形 |
| 固定事件序列 | 每类至少 15 次 | 同时记录召回和告警延迟 |

### 5.2 记录指标

| 指标 | 单位 | 说明 |
| --- | --- | --- |
| 平均电流 | mA | 固定场景的平均值 |
| 峰值电流 | mA | 采集、特征和推理峰值 |
| 平均功率 | mW | 在记录电压下计算或直接测得 |
| 累计能量 | mWh | 固定时长内的总能量 |
| 完整推理次数 | 次/分钟 | 反映计算节流效果 |
| 事件 Recall | % | 与 P0 同一用例比较 |
| 误触发率 | 次/分钟 | 无事件时的告警频率 |
| 端到端延迟 | ms | 平均值和最大值 |

节能率使用同一场景下的能量或平均功率计算：

```text
saving = (baseline_power - candidate_power) / baseline_power * 100%
```

不只报告最安静场景的节能率；至少同时报告安静和持续噪声两类场景。

## 7. 风险与应对

| 风险 | 后果 | 应对 |
| --- | --- | --- |
| 门限过高 | 远距离/小声事件漏检 | 用冻结测试集扫门限；保留最低探测和 ACTIVE 保持时间 |
| 门限过低 | 长期进入 ACTIVE，几乎不省电 | 报告真实收益；改进噪声地板估计而非掩盖结果 |
| 持续音乐/谈话 | 能量门控不能区分事件与噪声 | 将其作为最差场景；后续考虑轻量预筛或模型优化 |
| 关闭 I2S 产生盲区 | 短促事件完全漏检 | P3 仅作为高级候选，必须单独评测 |
| 只测平均电流 | 忽略推理峰值和识别退化 | 同时报告峰值、能量、Recall、FP/min、延迟 |
| 测量条件不同 | 对比无效 | 固定板卡、供电、外设状态、测量点和时长 |

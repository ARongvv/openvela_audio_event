# ccf_audioevent 目录架构说明

本文说明 `ccf_audioevent` 的源码、板级配置、模型、测试与文档如何组织。它面向需要构建、替换模型、
复现 ESP-NN 性能或新增测试记录的开发者。

> 本文只描述受版本管理的工程材料。`.built`、`.depend`、`Make.dep`、`*.o` 和 `out/` 均为构建过程
> 产生的文件，不是源码；其中 `out/` 已被 `.gitignore` 忽略。

## 1. 总体结构

```text
ccf_audioevent/
├── app/                         # NuttX applications：主应用、基准与采集工具
├── board/                       # ESP32-S3 与 Goldfish 的板级实现和 defconfig
├── docs/                        # 项目说明、基线、方案与调试文档
├── logs/                        # 演示材料与原始串口测试记录
├── scripts/                     # 建链、模型导入、资源镜像和数据分析脚本
├── test_data/                   # 可复现的板端输入 WAV 及事件时间线
├── third_party/esp-nn/          # 固定版本的 ESP-NN 上游源码
├── train/                       # 训练脚本及 small/medium/large 模型训练产物
├── archive/esp32s3-box-3/       # 已归档的 ESP32-S3-BOX-3 适配材料
├── LICENSE / NOTICE / THIRD_PARTY_NOTICES.md
└── readme.md                    # 项目总入口、接入 openvela 与构建说明
```

主业务数据流如下：

```text
I2S 麦克风或 WAV 文件
  → PCM 环形窗口 / 能量门
  → log-mel + delta 特征
  → TFLite Micro（可选 ESP-NN）
  → 事件判定
  → 串口、OLED/LVGL、告警与可选 HTTP 上报
```

## 2. `app/`：NuttX 应用

### 2.1 `app/audio_event/`：生产音频事件检测应用

这是构建后在 NSH 中运行 `audio_event` 的主要应用。`Makefile` 与 `CMakeLists.txt` 将 C/C++ 源码
接入 NuttX `apps` 构建；`Kconfig` 定义应用、模型 Arena、hop、能量门、显示和远程上报等配置项。

| 路径 | 主要文件 | 功能 |
| --- | --- | --- |
| `main/` | `audio_event_main.c` | 程序入口、命令行解析、实时采集与文件回放循环、1 秒环形窗口、`--profile` 输出及模块初始化/释放。 |
| `audio/` | `audio_capture.[ch]` | 打开 NuttX audio 设备，配置 INMP441/I2S 采集并转换为模型所需的 16 kHz 单声道 PCM16。 |
| `audio/` | `audio_file.[ch]` | 读取板端 LittleFS 或其他文件系统中的 WAV，供 `--file` 离线回放。 |
| `dsp/` | `feature_extract.[ch]` | KISSFFT 前端、log-mel 与 delta 特征提取，输出模型的 `[49, 40, 3]` 特征。 |
| `model/` | `event_classifier.cc/.h` | TFLite Micro interpreter、算子注册、量化/反量化和 Invoke 封装；ESP-NN wrapper 的选择发生在该推理路径中。 |
| `model/` | `model.cc/.h`、`model_int8.tflite`、`metadata.json` | 当前部署 INT8 模型的 C 数组、原始 TFLite 文件和模型元信息。替换模型时必须同步检查三者及 `event_classifier` 的 I/O 约束。 |
| `model/` | `bcresnet1_8class_preflight.cc`、`bcresnet1_8class_model.cc/.h` | BCResNet1 8-class 的独立预检路径，仅在 `tflm_benchmark` 开启对应 Kconfig 后编译，不替换生产 `audio_event` 模型。 |
| `power/` | `power_gate.[ch]` | 启动噪声标定、RMS/峰值能量门、低能量窗口跳过和 `infer/skip` 统计。 |
| `detector/` | `event_detector.[ch]` | 对分类概率进行连续命中、阈值与冷却判定，产生稳定事件结果。 |
| `alert/` | `event_alert.[ch]` | 串口/本地事件告警的抽象接口。 |
| `reporter/` | `event_reporter.[ch]`、`event_reporter_http.c` | 可选异步 HTTP 上报队列与发送实现；默认不启用，避免网络影响本地检测。 |
| `ui/` | `audio_event_ui.c`、`ui_*.c`、字体文件 | Goldfish 或带 LVGL 的大屏界面：波形、类别概率、状态、动画与参数展示。 |
| `ui_oled/` | `audio_event_oled_ui.[ch]` | ESP32-S3 DevKit 上 128×64 OLED 的轻量显示界面。 |
| `res/audio/` | `*.wav` | 随应用保存的少量样例音频；如需在板端播放，应通过 LittleFS 镜像脚本写入 `/data`。 |
| `audio_event_config.h` | 常量与应用级配置接口 | 定义采样率、窗口、类别等跨模块共享的应用配置。 |
| `docs/` | `架构文档.md` 等 | 应用内的历史设计、UI 与训练说明；项目级最新说明以仓库根 `docs/` 为准。 |

### 2.2 `app/audio_event/tflm_benchmark/`：独立模型基准程序

`tflm_benchmark/main/tflm_benchmark_main.c` 构建为独立 NSH 内建命令 `tflm_benchmark`。它复用
`model/` 中的模型和分类器，但不执行完整的 I2S/特征/事件告警链路，用于：

- `--mode invoke`：使用 ESP32-S3 CCOUNT 测量 `MicroInterpreter::Invoke()`；
- `--mode operator --csv`：输出 TFLM 算子级计时；
- ESP-NN reference、verify 和性能 profile 的数值验证与横向比较；
- BCResNet1 8-class 模型的内存/算子预检。

### 2.3 `app/audio_record/` 与 `app/audio_test/`

| 目录 | 入口文件 | 功能 |
| --- | --- | --- |
| `app/audio_record/` | `audio_record_main.c` | 从音频设备录取 PCM/WAV 相关数据并导出，便于获得真机样本。 |
| `app/audio_test/` | `audio_test_main.c` | 验证 I2S/INMP441 PCM 采集质量，辅助排查全零、声道、幅度与格式问题。 |

每个辅助应用均有独立 `Kconfig`、`Makefile`、`Make.defs` 与 `CMakeLists.txt`，以便被 NuttX `apps`
目录发现和编译。

## 3. `board/`：板级实现与构建 profile

### 3.1 `board/esp32s3-devkit/`

该目录通过软链接接入 openvela 的 ESP32-S3 DevKit board 路径，提供：

| 路径 | 功能 |
| --- | --- |
| `Kconfig` | 板级菜单、INMP441、OLED、Flash/LittleFS 等板级配置入口。 |
| `src/esp32s3_bringup.c`、`esp32s3_appinit.c` | 外设与应用启动初始化。 |
| `src/esp32s3_oled.c` | OLED 板级挂载与设备初始化。 |
| `src/esp32s3_*.c` | SPI、GPIO、按键、复位、TWAI 等 DevKit 通用板级支持。 |
| `include/board.h`、`board_memorymap.h` | 板级常量、内存映射与接口声明。 |
| `configs/*/defconfig` | 可被 `./build.sh ccf_audioevent/board/esp32s3-devkit/configs/<profile> -j8` 直接选择的构建配置。 |

### 3.2 `configs/` profile 分组

完整的使用场景、节点选择与构建命令见
[Reference 与 ESP-NN 性能对比操作手册](项目基线/Reference与ESP-NN性能对比操作手册.md) 和
[audio_event 与 ESP-NN 端到端对比](项目基线/audio_event与ESP-NN端到端对比.md)。此处只定义分组：

| 分组 | profile | 用途 |
| --- | --- | --- |
| 生产应用 | `audio_event` | 默认 ESP32-S3 音频检测应用，不启用 ESP-NN 测试选择。 |
| 8-class HTTP 联调 | `audio_event_8class_remote_http` | S3-large 8-class、全组合 ESP-NN、Wi-Fi/WAPI 与异步 HTTP reporter。凭据、endpoint 和 Token 不入库，使用串口 `wapi` 完成 STA 配网。 |
| 8-class 双核 HTTP 联调 | `audio_event_8class_remote_http_smp` | 在上述 HTTP profile 基础上启用 NuttX SMP 双核；音频主线程/采集固定 CPU0，HTTP reporter 固定 CPU1，用于单核与双核端到端对比。 |
| 8-class PCM 可视化 | `audio_event_8class_remote_pcm` | 单核 HTTP 基线加可选 UDP PCM streamer；音频帧经 PSRAM 有界队列发送至上位机 Canvas 波形，默认须使用 `--pcm-stream` 才实际传输。 |
| 端到端 ESP-NN | `audio_event_espnn_ref_profile`、`audio_event_espnn_verify`、`audio_event_espnn_profile` | 分别用于 reference 对照、真实特征逐字节验证和五卷积节点的端到端性能测试；均启用 `/data` LittleFS 资源分区。 |
| 常规/模型预检 | `tflm_benchmark` | 常规 TFLM 算子观察和 BCResNet1 8-class 预检。使用前应确认所需 Kconfig 选项，避免混用两种目的。 |
| 通用 ESP-NN 验证 | `tflm_benchmark_espnn_verify`、`tflm_benchmark_espnn_profile` | 早期/通用单节点或组合 ESP-NN 数值验证与性能观察。 |
| CCOUNT 基线 | `tflm_benchmark_espnn_cycles_ref` | 保留 ESP-NN wrapper 链接、但所有卷积回退 reference 的公平 Invoke 基线。 |
| CCOUNT 加速组合 | `tflm_benchmark_espnn_cycles` | 三个普通 Conv2D 节点（输出 tensor 23/25/27）使用 ESP-NN。 |
| CCOUNT Depthwise 回归 | `tflm_benchmark_espnn_cycles_dw24*`、`tflm_benchmark_espnn_cycles_dw26*` | 分别评估 DW24 或 DW26；后缀 `_verify` 开 TRACE/VERIFY，仅用于数值正确性。 |
| CCOUNT 全组合 | `tflm_benchmark_espnn_cycles_dw24_dw26*` | 三个 Conv2D 加 DW24、DW26；无后缀用于正式性能，`_verify` 用于组合数值验证。 |
| CCOUNT Mean | `tflm_benchmark_espnn_cycles_dw24_dw26_mean*` | 在五卷积组合上增加 axes `{1,2}` 的特化 ESP-NN Mean；无后缀用于正式性能，`_verify` 用于 Mean 的逐字节验证。 |

`defconfig` 是 profile 的版本化输入。建议通过 `menuconfig`/`savedefconfig` 生成稳定结果，提交前检查
是否仅包含有意的配置语义变化；不要把临时 `.config`、自动生成的无关头注释或构建产物混入提交。

### 3.3 `board/goldfish-arm64/`

`configs/audio_event/defconfig` 和 `config.ini` 为 Goldfish ARM64 模拟器配置源。它用于文件输入、模型
加载和 LVGL UI 的回归，不替代 ESP32-S3 真机性能或 I2S 结论。

## 4. `scripts/`：工程辅助脚本

| 脚本 | 功能 |
| --- | --- |
| `link_esp_nn.sh` | 将 `third_party/esp-nn` 建立为 openvela TFLM 所需的本地链接。构建任意 ESP-NN profile 前运行。 |
| `make_audio_event_littlefs_image.sh` | 把一个或多个 WAV 制作为 8 MiB LittleFS 镜像，目标地址为 N16R8 上半区 `0x800000–0xFFFFFF`。 |
| `import_bcresnet1_8class_model.sh` | 将验证过的 BCResNet1 TFLite 导入为预检 C/C++ 模型数组。 |
| `summarize_tflm_benchmark.py` | 汇总 `tflm_benchmark --csv` 的算子记录。 |
| `remote_receiver.py` | 远程 HTTP 告警上报功能的局域网接收端演示程序。 |
| `subset_font.sh` | 为 LVGL/OLED 资源裁剪字体。 |
| `fix_box3_*.sh` | 历史 ESP32-S3-BOX-3 构建兼容性修复，仅在归档 Box3 路径排障时使用。 |

## 5. 模型、训练、依赖与测试资产

| 路径 | 功能与维护原则 |
| --- | --- |
| `third_party/esp-nn/` | ESP-NN 上游源码副本；通过 `scripts/link_esp_nn.sh` 暴露给 openvela。除非确有 openvela 兼容性补丁，不应直接修改。 |
| `train/` | 训练脚本、训练日志、量化 TFLite、C 数组导出、混淆矩阵与指标。`small_clean`、`medium_clean`、`large_clean` 是不同规模模型的可追溯产物。 |
| `test_data/combined_A_pure.wav` | 可复现的无底噪 File A 板端测试音频。 |
| `test_data/combined_A_pure.json` | File A 的采样率、类别和事件时间线；应与 WAV 一同更新。 |
| `logs/测试日志/` | `picocom` 采集的原始 NSH 测试日志。文件名、模型、ESP-NN 组合和输入音频索引见 [logs/readme.md](../logs/readme.md)。 |
| `logs/演示/` | 面向展示的演示日志与视频，不与原始测试日志混放。 |
| `archive/esp32s3-box-3/` | 已归档的 BOX-3 历史适配和脚本，不是 N16R8 主线构建入口。 |

## 6. `docs/`：文档分层

| 目录 | 内容 |
| --- | --- |
| `比赛说明/` | 赛题范围、限制、评审要求和面向报告/答辩的项目成果总结。 |
| `项目基线/` | 当前模型、性能、基线对比、端到端实测和模型预检等已验证材料。 |
| `优化文档/` | ESP-NN 接入、推理时间和特征提取的优化实施方案、边界和验收流程。 |
| `使用与调试/` | 构建、录音导出、采集诊断、TFLM 算子剖析、模拟器与常见异常处理。 |
| `复赛目标/` | 尚在规划或分阶段验证的低功耗、双核、联网、鲁棒性和关键词识别方案。 |

`docs/README.md` 是文档导航入口；根目录 `readme.md` 是项目总入口和 openvela 接入说明。

## 7. 常见变更应落到哪里

| 变更目标 | 首选修改位置 | 同步检查 |
| --- | --- | --- |
| 替换部署模型 | `app/audio_event/model/` | 输入/输出形状、类别映射、算子 resolver、Arena、ESP-NN tensor 白名单与模型文档。 |
| 调整特征参数 | `dsp/feature_extract.*`、`audio_event_config.h` | 训练端特征定义、模型输入形状、真机精度与耗时。 |
| 调整报警策略 | `detector/`、`power/`、相关 Kconfig | 真机误报/漏报、能量门跳过率、日志与测试时间线。 |
| 调整 I2S/OLED/Flash | `board/esp32s3-devkit/` 与对应 `defconfig` | 板级 Kconfig 依赖、设备节点、LittleFS 地址及实际烧录布局。 |
| 新增 ESP-NN 测试 | 新建独立 `configs/tflm_benchmark_*` profile | 先使用 `_verify` 数值验证，再使用无 TRACE/VERIFY profile 测量 CCOUNT。 |
| 新增可复现 WAV 测试 | `test_data/`、`logs/测试日志/`、`logs/readme.md` | WAV 与 JSON 时间线同步提交，日志索引注明模型、后端、命令和结果。 |
| 仅更新板端 WAV | `scripts/make_audio_event_littlefs_image.sh` | 生成并烧录 LittleFS 镜像；不要提交 `out/` 生成文件。 |

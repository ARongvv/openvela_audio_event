# 事件定义与触发口径说明

本文档定义 `audio_event` 系统中各音频事件类别的语义边界、触发条件及其设计依据。

## 一、事件类别

`audio_event` 的模型输出 4 个类别：

| 索引 | 类别名称 | 语义描述 |
|------|----------|----------|
| 0 | **knock** 敲门声 | 物体敲击硬质表面（门板、桌面、墙壁等）产生的短促、宽带冲击型声音。特征：0.1–0.3 秒内完成起振-衰减周期，频域能量集中在 500 Hz–4 kHz 范围，有清晰的前沿瞬态。 |
| 1 | **cough** 咳嗽声 | 人类咳嗽动作产生的爆发性肺部排气声。特征：持续约 0.2–0.6 秒，包含喉部爆破（高频）和胸腔共鸣（中低频）两个阶段，频谱包络随时间快速衰减。 |
| 2 | **background** 背景环境音 | 不含上述事件的日常室内环境噪声，包括交谈声（远场）、电器嗡鸣、键盘敲击、脚步声、空调/风扇背景声等。频谱相对平坦、时域无明显突发瞬态。 |
| 3 | **silence** 静音 | 环境声压级长期处于接近量化噪声地板的状态。RMS 极低，零样本比例极高。 |

### 类别边界说明

- **knock vs cough**：两者均为短促爆发型声音，但 knock 来自非生物打击源（频谱干净，基频相对单一），cough 来自呼吸道（频谱更宽、有附加的摩擦和共鸣分量）。模型通过 mel 频谱的时频模式区分。
- **background vs silence**：background 允许包含常规日常噪声，silence 仅指长期保持声压极低的状态。中间过渡状态（偶尔极轻的摩擦声）可能被模型判定为 background。
- **background 涵盖的非目标事件**：以下声音按模型设计应归类为 background（除非信号强度异常接近训练集中的目标事件）：日常交谈、关门声（远距离）、脚步声、键盘鼠标点击、纸张翻动。
- **不在模型能力范围内的事件**（会被归为 background 或误判为某个目标类）：婴儿哭声、狗叫声、车辆鸣笛、风噪声（强风直吹麦克风）。

## 二、事件识别流程

```
┌──────────────┐     ┌──────────────────┐     ┌────────────┐     ┌───────────────┐
│ 音频采集      │ ──→ │ 滑动窗口特征提取  │ ──→ │ 模型推理    │ ──→ │ 检测器判决     │
│ 16k/16b mono │     │ 49×40×3 log-mel  │     │ int8 TFLite │     │ 阈值+连续命中  │
│ 1s 窗口      │     │ + delta           │     │ 4类概率输出  │     │ + 冷却管理     │
└──────────────┘     └──────────────────┘     └────────────┘     └───────────────┘
```

### 2.1 音频规格

- 采样率：16 kHz
- 精度：16-bit signed integer (mono)
- 分析窗口：1 秒（16000 采样点）
- 滑窗步长（hop）：250 ms（4000 采样点，可配置）

### 2.2 特征提取

每 1 秒窗口经以下处理生成 49×40×3 = 5880 维特征向量：

1. **分帧**：30 ms 窗口（480 点），20 ms 步进（320 点）→ 49 帧/秒
2. **加窗**：Hann 窗（周期窗），用于抑制频谱泄漏
3. **FFT**：512 点实数 FFT（KISSFFT），取幅度谱
4. **Mel 滤波器组**：40 个三角滤波器，覆盖 125 Hz–7500 Hz
5. **对数压缩**：`log(mel_energy + 1e-6) + 12.0`，缩放 ×1.625，钳位到 [0, 26]
6. **Delta 计算**：对每个 mel bin 计算一阶和二阶时序差分（N=2 加权回归），生成 3 通道特征图

特征提取的前端参数（mel 频带范围、滤波器数量、对数偏移/缩放）与 TensorFlow `tf.signal` 的输出在浮点精度内对齐。

### 2.3 模型推理

- 模型：TFLite Micro int8 量化 CNN
- 架构：2 层 conv2d + depthwise_conv2d + mean + fully_connected + softmax（9 个 op）
- 参数量：2148
- 模型大小：约 12 KB（`model_int8.tflite`）
- 输入：`int8[49][40][3]`（CHW 布局），量化 scale ≈ 0.0128
- 输出：`int8[4]`，去量化后得到 4 个 [0, 1] 概率值

### 2.4 检测器判决

检测器位于 `detector/event_detector.c`，对模型输出的逐窗概率进行**状态化过滤**，将噪声窗口中的零散高概率值过滤为有意义的告警事件。

## 三、触发口径

### 3.1 触发规则

一个事件类别**同时满足以下三个条件**时触发告警：

| 条件 | 默认值 | 配置项 |
|------|--------|--------|
| 概率 ≥ 阈值 | **750‰**（0.75） | `CONFIG_EXAMPLES_AUDIO_EVENT_KNOCK_THRESHOLD` / `CONFIG_EXAMPLES_AUDIO_EVENT_COUGH_THRESHOLD` |
| 连续命中窗数 ≥ N | **2 窗** | `CONFIG_EXAMPLES_AUDIO_EVENT_CONSECUTIVE_HITS` |
| 距上次告警 ≥ 冷却时间 | **1500 ms** | `CONFIG_EXAMPLES_AUDIO_EVENT_COOLDOWN_MS` |

### 3.2 各条件的设计依据

#### 概率阈值：750‰

`metadata.json` 中的模型训练指标：

| 指标 | 值 |
|------|-----|
| 测试集准确率 | 92.98% |
| 误报率 (false alarm rate) | 4.57% |
| 漏报率 (miss rate) | 2.27% |

阈值 750‰ 是一个**偏保守的工程选择**：

- 低于 750‰（如 500‰）→ 误报率显著升高。背景环境下 cough 或 knock 的概率在单窗内可能因环境噪声偶然达到 400‰–600‰。阈值过低会把这些零散的高概率窗口误判为事件。
- 高于 750‰（如 900‰）→ 漏报率升高。真实事件在模型输出中可能因距离/音量/遮挡等因素导致置信度在 700‰–900‰ 区间波动，阈值过高在连续命中机制之前就截断了部分真实事件。
- 750‰ 是在误报和漏报之间的平衡点。配合连续命中机制，误报和漏报均可进一步降低。

#### 连续命中次数：2 窗

单窗概率受瞬态噪声、特征量化误差影响，可能出现偶然尖峰。要求连续 2 窗命中：

- **抗噪效果**：真实事件（如咳嗽）的模型输出在滑动窗口内呈持续高置信度（2–4 窗连续 >750‰），而随机噪声尖峰通常只持续 1 窗。要求 2 窗命中可将单窗误报概率平方降阶。
- **延迟代价**：hop=250ms 时，2 窗命中的理论最大检测延迟为 250ms + 推理时长。对于告警类应用（非实时干预），该延迟在可接受范围。
- **可调范围**：若对延迟极度敏感（如用于触发后续录制），可将 `CONFIG_EXAMPLES_AUDIO_EVENT_CONSECUTIVE_HITS` 调为 1；若环境噪声较强，可调至 3 或更高以换取更低误报率。

#### 冷却时间：1500 ms

真实事件（咳嗽、敲门）很少在 1.5 秒内重复出现。冷却时间的作用：

- 避免单一事件被多次告警（如一次咳嗽被连续多窗检测到，只告警一次而非多次）。
- 使得连续命中计数器有足够时间重置，为下一次新事件做好准备。
- 1500ms / hop 250ms ≈ 6 窗，足以覆盖一个完整事件的所有高分窗口。

### 3.3 检测器状态机

```
          ┌──────────────────────────────┐
          │          IDLE (seek)          │
          │  candidate=-1  hits=0        │
          └───────────┬──────────────────┘
                      │ 概率≥阈值 且 best∈{knock,cough} 且 非冷却期
                      ▼
          ┌──────────────────────────────┐
          │        TRACKING              │
          │  candidate=X  hits=1         │
          │                              │
          │  下一窗 best=X → hits++      │
          │  下一窗 best≠X → 重置为新候选  │
          └───────────┬──────────────────┘
                      │ hits ≥ CONSECUTIVE_HITS
                      ▼
          ┌──────────────────────────────┐
          │          FIRE                │
          │  → event_alert_fire()        │
          │  → 进入冷却期 (1500ms)        │
          │  → 重置 candidate/hits        │
          └──────────────────────────────┘
```

关键行为：

- 候选类别（candidate）仅在概率 ≥ 阈值且类别为 knock(0) 或 cough(1) 时才参与跟踪。background 和 silence 永远不会触发告警。
- 如果在跟踪期间概率回落至阈值以下，或最佳类变为 background/silence，跟踪立刻重置：candidate = -1，hits = 0。
- 在冷却期内，所有候选跟踪均被抑制（包括不同类别的候选）。

## 四、典型运行序列举例

以下是一个咳嗽事件的典型模型输出序列（hop=250ms）：

| 时间 | 最佳类 | 置信度 | 检测器状态 |
|------|--------|--------|------------|
| t=1024 | background | 859‰ | IDLE（ignore） |
| t=1280 | background | 969‰ | IDLE（ignore） |
| t=1536 | background | 945‰ | IDLE（ignore） |
| t=1792 | background | 566‰ | IDLE（ignore） |
| **t=2048** | **cough** | **434‰** | IDLE（<750‰，ignore） |
| **t=2304** | **cough** | **914‰** | **TRACKING: candidate=cough, hits=1** |
| t=2560 | cough | 738‰ | IDLE（<750‰，重置） |
| t=2816 | cough | 621‰ | IDLE（<750‰） |
| t=3072 | cough | 629‰ | IDLE（<750‰） |
| t=3328 | cough | 691‰ | IDLE（<750‰） |
| **t=3584** | **cough** | **820‰** | **TRACKING: candidate=cough, hits=1** |
| **t=3840** | **cough** | **777‰** | **FIRE → ALERT**（hits=2 ≥ 2） |
| t=4096 | cough | 664‰ | COOLDOWN（ignore） |
| t=4352 | cough | 840‰ | COOLDOWN（ignore） |

从该序列可以观察：

1. **t=2560 时置信度（738‰）恰好低于 750‰ 阈值**，导致第一次候选跟踪被中断——这是阈值的正常截断行为。
2. **从 t=2048 到告警，cough 概率持续偏高跨越约 1.8 秒**，表明真实咳嗽音频段的模型响应是连续多窗的，而非单窗尖峰。
3. **告警后冷却期内即使仍有高声窗（t=4096、t=4352）也不再告警**，避免重复。

## 五、参数调优指南

### 减少漏报

| 调整方式 | 风险 |
|----------|------|
| 降低阈值（如 650‰） | 误报率升高 |
| 减少连续命中数（1） | 单窗噪声尖峰可能触发 |
| 缩短 hop（如 125ms） | 推理次数翻倍，CPU 负载增加 |

### 减少误报

| 调整方式 | 风险 |
|----------|------|
| 提高阈值（如 850‰） | 漏报率升高 |
| 增加连续命中数（3–5） | 检测延迟增加（N−1）× hop |
| 延长冷却时间 | 真实事件在冷却期内被忽略 |

### 调优方法

1. 先在目标环境中用 `--file` 或 `--device --audio-stats` 跑若干次代表性音频
2. 观察 `[infer]` 日志中目标类置信度的典型范围和波动幅度
3. 将阈值设为置信度中位数附近的整数值（如波动范围 600–950‰，设 750‰）
4. 连续命中数以"略大于单窗波动范围"为准（如波动 ±1 窗即回归 background，设连续 2–3）
5. 冷却时间 ≥ 目标事件最大持续时长（咳嗽约 0.6s × hop/2 ≈ 1500ms）

## 六、已知边界

1. **长尾噪声**：持续非平稳噪声（如扫地机器人由远及近经过）可能被模型误判为 cough 或 knock，通过提高连续命中数可以部分缓解。
2. **远距离事件**：3 米以外的咳嗽声在 60 dB 背景噪声下，模型置信度可能降至 500–650‰ 区间，低于默认 750‰ 阈值。若应用场景需要覆盖远距离，应降低阈值并接受更高的误报率。
3. **训练集分布外事件**：婴儿哭声、狗叫等未在训练集中出现的类别，模型大概率输出 background 或任意分布。不应依赖该模型检测训练集外的类。
4. **多事件叠加**：同时发生两个目标事件（如咳嗽的同时有人敲门），模型输出可能是两者之一的峰值或混合分布，结果不确定。
5. **INMP441 硬件信号问题**：使用 INMP441 麦克风时，如果 I2S slot/shift 配置不当，输入 PCM 可能带有 DC 偏移或幅度异常，导致 mel 特征分布畸变、模型输出不可靠。应先使用 `audio_test` 验证采集链路。
